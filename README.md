# Valuer Support — no-Docker project and A–Z setup guide

This edition runs on Windows with **Python + Node.js + SQLite**. Docker, WSL and a local PostgreSQL server are not required. After building the interface, one Python process serves the entire local application.

This is a development MVP with complete source for the features below, not a certified valuation product. Read `docs/VERIFICATION.md` for exactly what was tested and the remaining acceptance work. The clean Word template follows generic valuation sections; it is **not a pixel-exact copy of the confidential reference**. No original report, identifying sample content or original images are included.

## A. What is included

- Accounts with hashed passwords and user-owned reports.
- Reusable valuer and bank details; each report saves its own copy of those details.
- Property, assignment, building, findings and valuation input forms.
- Decimal land/building calculations, adjustments, rounding and amounts in words.
- Coordinates → authentic Google Maps Static API image, with preview and optional report insertion.
- Inspection photo upload and captions.
- Editable Word template; draft DOCX and PDF exports.
- Draft → review → final workflow, locked final archives and revised copies.
- Revision conflict detection and input history.
- Windows setup/run/check scripts, GitHub checks, and native Linux hosting instructions.

There is no AI plugin requirement. A map is retrieved from a mapping service, never generated by an AI image model. A coordinate locates a point; it does not identify legal parcel boundaries, verify ownership, or guarantee recent aerial photography. The valuer must verify the map and all report conclusions. Valuation rates and professional findings come from the valuer.

## B. Technologies and where to edit

| Part | Technology | Location |
| --- | --- | --- |
| Form/editor | React, TypeScript, Vite | `frontend/src/main.tsx`, `fields.ts` |
| API/auth/workflow | Python, FastAPI | `backend/app/main.py`, `security.py` |

| Maps | Google Maps Static API | `backend/app/maps.py` |

SQLite is bundled with Python. The database and tables are created when the backend starts. It is suitable for this small, single-server pilot; there is no database installation wizard.

## C. Install only these tools on Windows

1. **Python 3.12 (64-bit)** from https://www.python.org/downloads/windows/ — include the Python launcher (`py`).
2. **Node.js 22.x, at least 22.12** from https://nodejs.org/en/download — includes npm. Use the latest security patch in that series.
3. **Git for Windows** from https://git-scm.com/downloads/win — includes credential sign-in support.
4. **LibreOffice** from https://www.libreoffice.org/download/download-libreoffice/ — required for PDF generation and final approval; draft Word export can work without it.
5. Optional: VS Code as your editor. Microsoft Word is useful to check the final template, but is not required by the backend.

Internet is needed to install packages and request Google maps. After setup, ordinary local editing and map-free exports can work offline. Installed packages still use disk space; this edition avoids Docker images, WSL and a separate database server. Actual space use depends on your installed tools and saved photographs.

Open a **new Command Prompt** and check:

```bat
py -3.12 --version
node --version
npm --version
git --version
```

The commands in Windows sections use Command Prompt unless a block is labelled PowerShell. You do not need to activate a virtual environment or change PowerShell execution policy.

## D. Extract the project

Extract the ZIP to a short, writable location, for example:

```text
C:\Projects\valuer-support-no-docker
```

Open that folder. You should see `setup-windows.cmd`, `backend`, `frontend` and this README. Keep the active SQLite database on the local disk, not in a shared network folder or a live cloud-sync folder. Back up to a separate protected location instead.

## E. One-time setup

Double-click **`setup-windows.cmd`**, or run:

```bat
cd /d C:\Projects\valuer-support-no-docker
setup-windows.cmd
```

It creates `backend\.venv`, installs Python dependencies, generates `backend\.env` with a random signing secret, installs frontend dependencies using the lockfile, and builds `frontend\dist`. It never overwrites existing `.env` settings or deletes your data. If installation fails, read the terminal error, resolve it and rerun the script.

Manual equivalent, useful for seeing each step:

```bat
cd /d C:\Projects\valuer-support-no-docker
py -3.12 -m venv backend\.venv
backend\.venv\Scripts\python.exe -m pip install --no-cache-dir -r backend\requirements.txt
backend\.venv\Scripts\python.exe scripts\setup.py
cd frontend
npm ci
npm run build
```

Only `backend\.env` is used. Do not create a frontend API-key file. Do not copy a real `.env` into GitHub, a client delivery ZIP, or a chat message.

## F. Run it as a local application

Double-click **`start-local.cmd`**. Leave its window open and visit:

**http://127.0.0.1:8000**

Press Ctrl+C in that window to stop. Start the script again whenever you need the app. Data survives a restart. This mode binds to your own laptop only; it does not publish a website.

Use only one backend at a time. Stop `start-local.cmd` before using development mode below.

## G. Run it while developing

Open two terminal windows, or double-click each script:

1. `start-backend.cmd` — Python API on port 8000, automatic reload on Python edits.
2. `start-frontend.cmd` — interface on port 5173, automatic refresh on interface edits.

Open **http://127.0.0.1:5173** for development. The frontend forwards `/api` requests to the backend. API documentation is at http://127.0.0.1:8000/docs and the health endpoint is http://127.0.0.1:8000/api/health.

After changing frontend code, run `build-frontend.cmd` before returning to local application mode. If you first built the interface while the backend was already running, restart the backend: static serving is configured at startup.

## H. Create the first account

Use the registration screen with a strong, unique password. Registration is enabled for initial local setup. Before handing the app to a client, change this in `backend\.env` and restart:

```dotenv
ALLOW_REGISTRATION=false
```

The existing account can still log in. Additional accounts can be created privately from the server terminal:

```bat
cd /d C:\Projects\valuer-support-no-docker\backend
.venv\Scripts\python.exe -m scripts.create_user
```

Do not give the client your development password. The MVP does not have self-service password reset or separate administrator/reviewer roles. A report owner also performs its approval. Reloading the browser clears the in-memory sign-in token and may require signing in again.

## I. Make your first test report

Use invented data first:

1. Fill in the valuer profile; save bank details for reuse.
2. Create a report and complete assignment, property, findings and valuation tabs.
3. Choose land-only or land-and-building, enter extents/rates and repeating floor rows as appropriate.
4. Leave map inclusion off for the first report, so no Google account is needed yet.
5. Save, calculate and inspect missing-field/review issues.
6. Export a draft DOCX and inspect it in Word or LibreOffice.
7. Export a real PDF and check every page.
8. Complete required fields, submit for review and approve only after checking the result.
9. Download the final files; use the revised-copy function for later changes.

Optional descriptive inputs remain blank/marked not supplied rather than inheriting another property's facts. Values such as forced-sale and insurance values are supplied by the valuer rather than invented automatically. See `docs/ARCHITECTURE.md` for workflow details.

## J. Configure real map snapshots

The backend requests an image for the entered latitude, longitude, map style and zoom. Standard Google Maps Static API setup needs an API-enabled Cloud project, billing and an API key. See the official [overview](https://developers.google.com/maps/documentation/maps-static/overview) and [request guide](https://developers.google.com/maps/documentation/maps-static/start).

1. Create a separate Google Cloud project for development. The client should own the production project and billing account.
2. Enable **Maps Static API**. You do not need the JavaScript Maps API or an AI subscription for this implementation.
3. Create a server API key and restrict it to this API. Apply appropriate server IP restrictions for a production server; a browser-referrer restriction is not appropriate for these backend requests. Development internet IPs can change.
4. Set usage quotas and billing alerts. Review current [Google Maps pricing](https://mapsplatform.google.com/pricing/); an alert alone does not stop usage.
5. Put the key in `backend\.env`, then restart the backend:

```dotenv
GOOGLE_MAPS_API_KEY=your-own-server-key
GOOGLE_MAPS_SIGNING_SECRET=
MAP_REPORT_EXPORT_ALLOWED=false
```

The signing secret is optional configuration if you use Google's URL-signing setup; it is different from the API key. Keep both private. Select map inclusion, enter coordinates, save and preview the location.

**Report embedding needs its own permission check.** An API key and successful preview do not establish permission to embed, store and distribute Google imagery permanently in commercial DOCX/PDF reports. Confirm your intended report/export/archive use against your Google agreement and applicable [Google Geo guidelines](https://about.google/brand-resource-center/products-and-services/geo-guidelines/), obtaining permission/licensing if needed. The package deliberately blocks map-containing report exports until the operator explicitly sets:

```dotenv
MAP_REPORT_EXPORT_ALLOWED=true
```

That flag is an operator acknowledgement, not a licence. Retain the entire image and its attribution. Until this use is cleared, test exports with map inclusion off. The app does not yet implement another map provider; choosing a provider whose licence expressly covers this workflow would require replacing the map adapter.

Coordinates and optional access-path coordinates go to Google when a map is requested. The application does not send the report document, applicant names, bank details or photographs to Google. Previewing, exporting and finalising can each request images; map requests are not necessarily one per report. No map caching system is implemented.

## K. Configure PDF conversion

The setup script looks for LibreOffice in standard Windows install locations. If it was installed later or elsewhere, edit `backend\.env`:

```dotenv
SOFFICE_PATH="C:/Program Files/LibreOffice/program/soffice.exe"
```

Restart the backend. Confirm the file exists, then export an actual PDF. The backend uses a separate temporary LibreOffice profile per conversion. The client machine/server must have fonts suitable for the template; substitution can change pagination. Word-only draft export does not prove PDF conversion works. Final approval requires successful conversion and archives both formats.

## L. Change the report template

Open `backend\templates\valuation-v1.docx` in Word and follow `docs/TEMPLATE.md`. Keep placeholders intact. Template edits affect new exports; existing final archives keep their original bytes.

The template generator is at `backend\scripts\create_template.py`. Running it overwrites the clean template, so first preserve any manually customised template. To add a new input end to end, update:

1. `backend/app/schemas.py` for validation/defaults.
2. `frontend/src/fields.ts` and/or `main.tsx` for the form.
3. `backend/app/reporting.py` if computed values or image context are needed.
4. The Word placeholder and relevant calculation/workflow checks.
5. The example schema documentation if you change inputs.

Get the intended valuer/bank to approve actual populated report pages. The reference layout, wording and bank requirements still need professional adaptation and acceptance.

## M. Connect the source to GitHub

Create a **private, empty repository** named `valuer-support` in your GitHub account. Do not initialise it with a README, licence or gitignore because these project files already exist. These steps follow [GitHub's local-code guide](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).

From the extracted project root:

```bat
cd /d C:\Projects\valuer-support-no-docker
git init -b main
git config user.name "Your Name"
git config user.email "YOUR_GITHUB_EMAIL_OR_NOREPLY_ADDRESS"
git check-ignore backend/.env backend/data/valuer.db frontend/node_modules
```

The last command should list those excluded paths after setup. `.gitignore` excludes local settings, databases, report storage, virtual environments and build dependencies. It cannot protect sensitive files you place somewhere else: keep real reports and the confidential reference outside the source tree.

Then inspect and commit:

```bat
git add .
git diff --cached --stat
git diff --cached --name-only
git status
git commit -m "Initial no-Docker valuer support project"
git remote add origin https://github.com/YOUR_USERNAME/valuer-support.git
git push -u origin main
```

Replace `YOUR_USERNAME` before running. Review staged filenames before committing; no real `.env`, database, report exports, personal photographs or original reference report should be staged. Use Git Credential Manager's GitHub sign-in prompt; do not put a token into the repository URL. If a key was committed, revoke/rotate it and follow GitHub's sensitive-data removal procedure—deleting the latest copy does not remove history.

If this folder already has Git history, do not reinitialise or replace remotes blindly: use `git status` and `git remote -v` to inspect the existing setup. If your online repository already has commits, clone it into a new folder and copy these source files into the clone instead of forcing a push.

GitHub stores source and runs checks. It does not automatically host the Python backend or SQLite data. No repository was created or pushed by this package.

## P. Where the data lives and how to back it up

Default locations relative to `backend`:

| File/folder | Meaning |
| --- | --- |
| `.env` | Private local settings and keys |
| `data/valuer.db` | Accounts, reports, profiles, history and photo references |
| `data/photos/` | Private uploaded images |
| `data/final/` | Locked final DOCX/PDF files and manifests |
| `templates/valuation-v1.docx` | Current report layout |

For a simple consistent backup, **stop the backend first**, copy the entire `backend\data` folder and the template to a protected backup location, and restart. Protect `.env` separately as a secret. Backing up only the database loses the attachments and final files; GitHub is not a report backup.

Example PowerShell, after stopping the app (choose your own protected destination):

```powershell
$backupFolder = "D:\ValuerBackups\$(Get-Date -Format yyyyMMdd-HHmmss)"
New-Item -ItemType Directory -Path $backupFolder | Out-Null
Copy-Item .\backend\data -Destination $backupFolder -Recurse
Copy-Item .\backend\templates -Destination $backupFolder -Recurse
```

To test restoration, use a separate installation with the same source release, stop its backend, preserve/move its existing test data out of the way, restore the saved `data` folder and template, configure its private settings and start it. Confirm login, photographs and final downloads. Do not overwrite the only live copy while testing a restore. Encrypt backups, limit access and agree retention with the client.

## Q. Give this to another person as a product

Two delivery choices:

**Local pilot:** give the client a clean source release and this guide, install Python/Node/LibreOffice, run setup on their computer, create their account, verify reports together, then disable registration. They use `start-local.cmd` and the browser. Their data stays on that computer unless they export it or a map request sends coordinates to Google. They do not need GitHub to use it.

**Hosted pilot:** deploy one central server using `docs/HOSTING-NATIVE.md`; give the client an HTTPS URL and their own account. Their data then lives on that server. The server, backups, domain and Maps billing should be in agreed client-owned accounts.

Build a clean release from committed source, so local data is excluded:

```bat
git archive --format=zip --output=..\valuer-support-v0.1.0-source.zip HEAD
```

This is a source release: dependencies and compiled frontend are recreated by setup. Do not send your virtual environment, credentials or database. Agree source ownership, third-party licence obligations, maintenance, backup responsibility and support terms. The included app does not implement subscriptions or payments.

Before wider commercial use, complete target-machine testing, professional template approval, dependency/security review, restore testing and privacy/access arrangements. Multi-organisation SaaS needs additional design: administrator/reviewer roles, account recovery, tenant controls, monitoring, queued exports and schema migrations. Those are not implemented features of this MVP.

## R. Hosting without Docker

You can deploy the same source directly on a Linux server: Python virtual environment, built frontend, SQLite on persistent local storage, LibreOffice, systemd and an HTTPS reverse proxy. See **`docs/HOSTING-NATIVE.md`** for the sequence and configuration files.

Do not put this whole application on GitHub Pages: it needs a Python process, writable data and PDF conversion. Do not place SQLite/report files on ephemeral deployment storage. Keep one API worker for this pilot; rate limiting is in memory and SQLite is a single-server database. Optional PostgreSQL dependencies are in `backend/requirements-postgres.txt`, but switching databases requires an explicit data migration, not just an environment-variable change.

Local use has no hosting subscription, although hardware, internet and Maps usage are separate. Hosting, domains, backups and usage-based APIs may cost money. Choose a host only after confirming persistent disk, native Python and LibreOffice support; free tiers may not meet these requirements.

## S. Reduce laptop disk usage

- Keep one working copy, one `.venv` and one `node_modules` folder.
- The setup uses pip's `--no-cache-dir`; do not install a local PostgreSQL server for this edition.
- Store photo/report backups on a suitable separate protected disk.
- After a successful build, if you only need local application mode, you may remove **only** `frontend\node_modules` using File Explorer. Keep `frontend\dist`. Recreate dependencies with `npm ci` before developing/building again.
- Do not delete `backend\data`, `.env`, the template or the Python `.venv` as a space-saving step.

## T. Troubleshooting

| Problem | What to do |
| --- | --- |
| `py` not found / 3.12 unavailable | Install Python 3.12 with its launcher and reopen the terminal. |
| `npm` not found / Node engine error | Install supported Node 22.x (22.12+) and reopen the terminal. |
| PowerShell blocks npm.ps1 | Use Command Prompt or `npm.cmd`; scripts already use `.cmd`. |
| API cannot be reached | Confirm backend window has no startup error and port 8000 is free. |
| Port 8000 already in use | Stop the other project backend with Ctrl+C; don't run both backend modes. |
| Port 5173 changes | Close another Vite instance; use 5173 to match configured CORS origins. |
| Page at 8000 is 404 | Build the frontend, then restart backend; or use 5173 in development mode. |
| `JWT_SECRET` missing | Run `scripts/setup.py` and launch from `backend`, as the supplied scripts do. |
| Changes not visible at 8000 | Rebuild frontend; development changes are immediately visible at 5173. |
| PDF export fails | Check installed LibreOffice, `SOFFICE_PATH`, writable temp space and fonts. |
| Map preview fails | Check key, billing, enabled Maps Static API, restrictions, quota and internet. |
| Map export blocked | Resolve report-image rights before enabling the explicit export setting. |
| Database locked | Keep data on local disk and use one backend; stop unintended duplicate processes. |
| Report changed error | Reload the latest revision and reapply your unsaved changes. |
| Git push authentication fails | Sign in through Git Credential Manager and check repo access/remote URL. |
| CI fails | Open the failing Actions log; fix it before treating the release as accepted. |

For non-Windows development, create `backend/.venv` with Python 3.12, install requirements, run `python scripts/setup.py`, then start uvicorn **from backend** and `npm run dev` from frontend. The application code is shared; Windows `.cmd` scripts are just launch conveniences.
